# Benchmark contamination

Training data that contains evaluation items inflates benchmark scores. The contamination
stage compares every document with protected benchmark material and reports or removes
overlaps.

## Benchmark registry

Benchmarks are configured separately from sources, in a registry file referenced by
`stages.contamination.registry` (the repository ships
`benchmarks/contamination/registry.yaml`). Each entry declares:

| Key | Meaning |
| :--- | :--- |
| `path` | Local JSONL file, relative to the registry's `base_dir` |
| `fields` | Which item fields to protect (for example `question`, or `prompt` and `canonical_solution`) |
| `id_field` | Item id field; line numbers are used when absent |
| `license`, `source_url`, `description` | Recorded in the manifest and dataset card |
| `required` | When `false`, a missing file is skipped and reported as "not available locally" |

DataForge never downloads benchmark material. The repository ships two synthetic,
CC0-licensed demo sets (`demo_math`, `demo_code`) generated by
`dataforge.synthetic.benchmarks`; a test keeps the committed files identical to the
generator. GSM8K, HumanEval, and MBPP are registered as optional local copies that an
operator fetches manually under their licenses (see the README in each directory).
`stages.contamination.benchmarks` limits the check to a subset; an empty list means every
available benchmark. Each benchmark file's SHA-256 is part of the stage fingerprint, so
fetching or changing a benchmark creates a new dataset version.

## Probes and normalization

Every non-empty protected field of every item becomes a *probe*. Probe and document text
are normalized for matching: lower-cased, every run of non-word characters (including `_`)
collapsed to one space. Word n-grams are hashed exactly like near-dedup shingles.

## Methods

Checked in order, strongest first; a probe matched by a stronger method is not reported
again by a weaker one.

| Method | Match condition | Score |
| :--- | :--- | :--- |
| `exact` | The normalized document equals a normalized probe (SHA-256 comparison) | 1.0 |
| `substring` | Every distinct word `ngram_size`-gram of the probe occurs in the document **and** the normalized probe is a literal substring of the normalized document | 1.0 |
| `ngram` | At least `ngram_threshold` of the probe's distinct `ngram_size`-grams occur in the document (containment, as in GPT-3-style decontamination) | the overlap fraction |
| `minhash` | Whole-document MinHash similarity with the probe is at least `minhash_threshold`, using an LSH index over probe signatures | the estimated Jaccard similarity |

Defaults: `ngram_size` 8 words, `ngram_threshold` 0.5, `minhash_threshold` 0.8,
`minhash_num_perm` 128, `shingle_size` 5. The n-gram index is a sorted array of
(n-gram hash, probe) postings queried with vectorized NumPy operations.

## Evidence without leakage

Matches are written to `reports/contamination.jsonl` with the document id, source, benchmark,
item id, field, method, score, matched and total n-gram counts, up to
`max_evidence_spans` (5) merged character-offset spans in the corpus document, and an
`evidence_hash`: the first 16 hex characters of the SHA-256 of the normalized probe. Benchmark
text is never copied into reports. Matched documents also carry the matches in their
`contamination` column (benchmark, item, method, score).

The report's contamination table counts *Exact* (exact and substring) and *Near* (n-gram and
MinHash) matches, documents affected, and items matched per benchmark.

## Policies

| `policy` | Behaviour |
| :--- | :--- |
| `drop` (default) | Remove contaminated documents (reason `contaminated`) |
| `flag` | Keep them and record the matches |
| `fail` | Stop the run at the first contaminated document with `ContaminationDetected` (exit code 8); useful as a CI gate |

`dataforge contamination scan CONFIG` runs the pipeline up to this stage in annotate mode and
prints the per-benchmark table without removing anything.

## Limitations

- **Paraphrases below the threshold pass.** Rewording more than about half of a probe's
  n-grams, or translation, defeats both n-gram containment and whole-document MinHash.
- **Short probes are only checked by `exact` and `minhash`.** A field with fewer words than
  `ngram_size` (short answers, one-line solutions) has no n-grams to index.
- **Templated benchmarks match sibling items.** When items share a template and differ only
  in numbers or names, a document containing one item can also exceed the n-gram threshold
  for its siblings; the report then lists more items than documents.
- **Containment versus similarity.** MinHash only catches documents that are close to the
  probe as a whole; benchmark text embedded in a long document is caught by `substring` and
  `ngram`, not `minhash`.
- Detection quality depends on having the benchmark locally; unavailable benchmarks are
  reported as such, never silently assumed clean.
